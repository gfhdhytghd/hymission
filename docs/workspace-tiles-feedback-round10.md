# Stage integrated workspace transitions (FB10)

## Single-column regression boundary

The task starts at `5df9917`. The loadable pretiles development reference is `552bd339fe4809e0a031d277ca97f4dac6d0a5da`; its archived source matches `build-tiles/reference-src` byte-for-byte for Stage. `origin/master` retains the same Stage flight and swipe design, but targets the older window/workspace ABI (`desktop/view/Window.hpp`, `m_id`, `m_isFloating`). It is compared as source, not loaded into the e5a03b6 compositor as if ABI-compatible.

The history boundary for the single-tile card regression is `b38136c60d4f3c2f41a7bc97d833976f15c3210e`, which introduced `nativeCardActivation`. That flag explicitly bypasses Stage workspace-animation ownership and excludes the synchronous pending-flight preparation when a card is clicked with one enabled tile. The request to retain the native `changeWorkspace` call was implemented as a request to use its native slide, losing Stage's card-to-desktop flight. Keeping the native workspace action does not require giving it visual ownership.

Both boundary revisions were independently archived, compiled against the matching release headers, and tested in private compositors: `b38136c^` passes the card flight/progress checks; `b38136c` fails both. The current pre-fix binary also fails only the card route in the single-tile case. Removing this flag restores all key, relative, card and four-finger routes in the single-tile case. Native `changeWorkspace` still commits the switch.

The reported tiles-off animation loss is **not reproduced** in the controlled dwindle or scrolling cases: the current pre-fix binary and pretiles reference both produce Stage flights for keys, relative selectors, cards and swipes. No separate tiles-off cause is claimed. The off-mode reference remains a required control for the multitile changes.

Private artifacts: `build-tiles/fb10-reference`, `fb10-before-{off,single,two}`, `fb10-before-off-scrolling`, `fb10-bisect-{good,bad}`, and `fb10-single-fixed`. Each route records Stage state, every-rendered-frame native framebuffer readback, and native window/workspace state. These establish private compositor behavior, not physical device or host-session acceptance. No push or host reload is performed.

## Delayed empty-workspace lifecycle

The release smoke exposed another single-tile failure after removing the native bypass: an empty outgoing workspace remains alive through the tile binding lease during native activation, then dies in the deferred single-tile reconcile. Stage has already prepared three incoming window flights. The subsequent card-list change cleared all flights via `!switching && (changedCards || changedGeometry)`. The trace records `77 -> 198`, three flights with 220 ms duration, followed by an empty flight list before the next assertion. This was not a fullscreen or rendering-cost failure.

The broad invalidation guard originates in `3ce7c3b6d6fca38487dcfecb42fed47079f59121`, the original card/desktop flight feature. The delayed lease lifetime makes it observable on the tile branch. Reconfiguration, output changes, suspension and cover still invalidate flights; ordinary card-list changes now prune invalid members and preserve valid incoming windows. Departing card endpoints follow their current card layout. The release smoke's empty-desktop case and an explicit empty-source single-tile case now complete their flights. The archived pretiles off-mode empty-source control also passes; this is not presented as a reproduced universal off-mode failure.

## Multitile implementation

The old explicit `ownsTransition` multitile rejection and `!clustered` pending-flight exclusion are removed. Ownership resolves the workspace's column, and tile publication synchronously prepares Stage before the first render. Cached card frames, desktop endpoints and scrolling viewports use the actual shared-output transform and the correct per-tile left-side band. Unrelated tiles' native position/size animations are not warped. The initial FB10 implementation restricted flights to the owning desktop and column. [FB12](workspace-tiles-feedback-round12.md) supersedes that clipping policy: moving flights use native Stage's output plane above stationary columns, while neighbor geometry and pixels outside flight footprints remain unchanged.

Stage swipe state carries the tile ID through preview, cancellation and settle. Per-column drawing, native-window suppression, state export and liveness select that column's visual scene. Native gesture initialization bypasses the tile-native slide layer only after Stage acquires the shared owner; updates remain in the original trackpad/unified event chain. Candidate selection is shared with FB9's ownership resolver, including wrap/create boundaries and named-workspace order. No second tile swipe or native workspace animation runs under Stage. Source/target fullscreen policies, disabled animations and lifecycle cancellation retain the existing guards.

The workspace strip is an overview surface: while overview is visible, overview retains the single visible animation owner and Stage stays suspended. Clicking a column changes only that tile; closing overview hands off to prepared Stage card/desktop endpoints. It does not forcibly close overview or add a second animation. Private three-column strip click/handoff captures verify this contract.

## Frame methodology

Each private run uses real Wayland clients, real private keyboard events, and four-finger device swipe events through InputManager/trackpad matching. No dispatcher is substituted for the swipe path. Native framebuffer readback records every rendered frame. The test fixture requests full-output damage during recording so unchanged regions have valid pixels; reading a partially damaged workbuffer would otherwise produce black stale regions. Startup watchdog notifications are disabled only in the private config, avoiding unrelated notification motion in neighbor comparisons. Cursor locations are masked in pixel-difference checks.

Stage phase is sampled before synchronous GPU readback, which otherwise advances the clock and misaligns a rendered image with its reported phase. The pretiles/reference/off/single runs compare actual blue-client pixel bounds: card/desktop endpoints within two pixels, every sampled middle-frame rectangle within four pixels of the same path, and width progress following the original cubic curve within 0.04 phase. Existing source easing/duration functions are retained; shrinking flights retain their original position curve. Four-finger held phases are included. This is phase-aligned rendered geometry equivalence, not a claim that nondeterministically scheduled compositor frames have identical wall-clock timestamps or byte-identical full images.
