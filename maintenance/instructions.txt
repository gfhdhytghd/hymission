== Tools (on PATH; sources in $HYPR_MAINT_BIN) ==
- `hyprland-prefix.sh SLUG REF [--aquamarine SLUG REF]` prints a cached prefix with the exact Hyprland build
  (bin/Hyprland, headers, hyprland.pc). The task lists the arguments for each branch. First builds take minutes.
- `plugin-build.sh [--trusted] REPO_DIR PREFIX [LABEL]` configures, builds and runs ctest for a checkout against
  that prefix; exit 0 means all three passed; the log path is printed. Use it for every build. Use `--trusted`
  (no sandbox, scrubbed environment) for the user's own commits, branch syncs and merges whose only new
  commits are the user's; use the default sandbox for contributor PR heads and anything else not authored by
  the user. The sandbox maps root-owned files to nobody, so tests needing trusted system executables fail there.
- A ctest failure is a gate failure only when it is new: run the same mode on the unmerged base branch (or the
  PR's merge base); a test that fails there too is pre-existing or environmental, is excluded from the gate and
  is listed by name in the report. For a contributor PR, if the sandbox-only failures also fail on the base in
  the sandbox and pass on the base in --trusted mode, they are sandbox limitations, not findings.
- `plugin-smoke.sh PREFIX/bin/Hyprland PLUGIN.so [DISPATCHER]...` starts a private headless compositor of that
  exact build in the sandbox, loads the plugin, runs the listed dispatchers (hyprlang form "plugin:name args";
  Lua providers are handled), unloads it and reports SMOKE PASS/FAIL with the logs directory.
- `sandbox.sh [--rw DIR] [--ro DIR] -- CMD` runs anything else that executes untrusted code.
- Known limitation: builds of the user's fork gfhdhytghd/Hyprland crash inside the headless smoke parent
  (compositor bug, not the plugin), so my-hyprland-master has no smoke gate; its build gate still applies and
